# v0.6.1 安全更新

**旧版本存在安全问题，请尽快升级并检查凭据。** 本次修复不意味着对整个项目及所有依赖完成了安全审计。

## 已确认的影响范围

- **v0.6.0 及修复前的 master：本地挂载路径越界。** 开启本地挂载时，目录、README 和文件操作未限制在挂载根目录内，可能暴露服务进程有权读取的其他文件。持有管理密钥的请求还可能在挂载范围之外创建、上传或删除文件。默认管理密钥是公开值，旧实现也未在所有写入入口统一检查 `enable_write`。
- **v0.6.0 及修复前的 master：凭据暴露。** 配置示例曾包含共享应用密钥；启动、OAuth 和请求日志可能包含管理密钥、目录密码、令牌、授权码或带授权参数的链接。历史日志和 Git 历史中的旧值不会因升级自动失效。
- **包含 WebDAV 的旧 master（功能引入提交 `95e92de` 起、修复前）：WebDAV 密码校验错误。** 启用 WebDAV 时，输入密码错误地与账号名比较，配置的密码未被使用。**v0.6.0 标签不包含 WebDAV，因此不属于这一项的受影响版本。**
- **v0.6.0 及修复前的 master：下载拒绝后继续执行、HTTP 资源处理缺陷。** `.password` 下载处理缺少立即返回；HTTP 请求未统一关闭响应体、检查状态码或限制时长，可能导致错误处理失效及资源占用。本公告未将缺少返回单独描述为已证实的远程密码文件泄露。

更早标签未逐一验证；请旧版本用户一并升级。以上为代码及本地回归测试确认的问题，不代表已发现线上攻击事件。

依赖检查另发现旧依赖锁定版本触发 GitHub Dependabot 的严重/高危告警（包括 `x/crypto`、`x/net`、`x/oauth2`、Logrus），以及 Gin 的中危告警。本次同步升级这些依赖。升级前的 `govulncheck` 没有发现可达的易受攻击函数调用，因此依赖告警不等于已经证实这些漏洞能在本项目中被利用。

## 修复

- 使用 Go `os.Root` 隔离本地文件读写、目录列表和 README；限制挂载名称、路径和上传文件名，拒绝路径越界及越界符号链接（包括检查与操作之间的链接替换）。
- 校验实际配置的 WebDAV 密码，鉴权失败立即停止请求，严格匹配挂载前缀，并遵守全局写入开关。
- 阻止 `.password` 经 HTTP 和 WebDAV 下载；在服务层增加校验；拒绝后立即返回。
- 移除模板中的共享凭据；拒绝旧公开应用密钥、空或过短的管理/WebDAV 密钥；关闭写入时统一拒绝修改请求。
- 日志不再输出完整配置、OAuth 令牌、目录密码、查询参数和上游响应正文；保留旧客户端协议，但部署方仍需配置反向代理，避免记录含凭据的查询参数。
- HTTP 响应体在成功及失败时均关闭；检查状态码；增加请求时限；仅对可安全重试的读取请求重试。上游上传失败不再返回成功。
- 升级 Gin、Logrus、`golang.org/x/crypto`、`x/net`、`x/oauth2` 及必要传递依赖（包括 quic-go 的 QPACK 资源耗尽修复），并锁定已移除不安全 OpenPGP 包的 x/crypto 修复提交；构建工具链提升到 Go 1.26.10。
- 修复相关测试的配置依赖和共享测试数据问题，加入路径隔离、鉴权、日志脱敏和 HTTP 错误处理回归测试。

## 升级与兼容性

1. 暂停旧实例对公网提供服务，备份配置、令牌和数据，再替换为本 release 的程序。不要把 `config.yml`、`.token`、数据库或日志放进共享目录。
2. 使用自己注册的 OneDrive / 世纪互联应用，填写自己的 `client_id` 和新 `client_secret`。模板现在留空；旧共享密钥将被拒绝。
3. 轮换曾出现在仓库、日志或默认配置中的管理密钥、WebDAV 密码、目录密码及应用密钥。若令牌可能泄露，请通过身份提供方撤销旧授权/令牌，再重新登录；仅删除本地 `.token` 不等于撤销远端令牌。
4. 开启写入时，`admin.secret` 至少 16 字符，建议使用随机生成值。开启 WebDAV 时，密码至少 12 字符且不能等于账号名。`admin.enable_write: false` 现在也会拒绝本地及 WebDAV 修改操作。
5. 检查和限制历史日志访问，移除日志中的敏感内容；检查反向代理是否记录 URL 查询参数。共享根目录应是专用文件目录。
6. 源码构建要求 **Go 1.26.10+**；安装包已包含编译好的程序及 v0.6.0 前端，无需安装 Go。二进制与前端版本独立。

验证：`go test -race ./...`、`go vet ./...`、`govulncheck ./...`，并构建 Linux（386/amd64/arm/arm64）、Windows（386/amd64）、macOS（amd64/arm64）安装包。此处不宣称已完成真实 OneDrive 账号的在线端到端验证。
